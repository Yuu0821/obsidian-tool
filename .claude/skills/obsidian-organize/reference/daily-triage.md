# 日次ノート仕分け 手順

デイリーノート(`日記メモ/YYYY-MM-DD.md`)は階層化された箇条書きで、1日の中に複数の話題が混在している。これをトピックごとに既存/新規のノートへ振り分ける。

## 手順

1. **対象範囲の確定**
   - ユーザー指定がなければ「まだ振り分けていない直近のデイリーノート」を対象にする。目印がなければユーザーに期間（例: 直近1週間、先月分）を確認する。

2. **読み込みとブロック分解**
   - 各デイリーノートをそのまま読み込む。トップレベルの箇条書き項目（1階層目の見出し的な項目、例: `保険`, `開発`, `仕事`）を1つの「話題ブロック」とみなし、その配下のインデントをまとめて1ブロックとして扱う。
   - 1ブロックが複数の話題を含む場合はさらに分割してよい。逆に1〜2行程度の断片的なメモは無理に分割せず「雑多メモ」として扱う。

3. **振り分け先の決定**
   - 各ブロックについて、Vault内の既存フォルダ・既存ノートに近いトピックがないか調べる（`Glob`でフォルダ一覧、`Grep`でキーワード一致するノートを探す）。
   - 既存ノートに追記できる内容なら追記、フォルダはあるが該当ノートがなければそのフォルダに新規ノート作成、フォルダ自体がなければ新規トップレベルフォルダの作成を提案する。
   - 判断に迷うブロック（複数トピックにまたがる、そもそもトピック性が薄い雑談・感情メモなど）は無理に分類せず、「未分類」として明示的にユーザーに提示する。分類先が明らかに存在しない一過性の日記的内容は、日記メモ内に残したままでよい。

4. **ユーザーへの提案**
   - 「このブロックはこのノートへ」という対応表を箇条書きで提示してから実行する。少数（目安5件未満）かつ迷いのない対応のみ、確認なしで進めてよい。

5. **実行**
   - 移動先ノートの末尾（または適切な見出し配下）に、元の箇条書き階層を保ったまま追記する。移動先ノートの既存の書式（見出しレベル、箇条書き/文章、語尾など）に合わせる。
   - ブロックの最後（文末）に、その内容がいつのデイリーノートに書かれたものかをイタリック体で添える。例: `- 足がすくむようなところに行った方がいい？ *(2026-05-09)*`。日付を見出しにしたり太字にしたりして目立たせない（あくまで内容が主役）。同じトピックに複数日の内容が積み重なるノートでは、各ブロックの文末にそれぞれの日付を付ける。
   - 移動元のデイリーノートは削除しないが、「振り分け済み」の注記やリンクも付けない（ユーザーはデイリーノートを見返さない運用のため）。移動先ノート側に日付さえ残っていればよい。
   - 内容を移動する前に、必ずそのデイリーノートを直接読んで日付と内容の対応を確認すること。会話の中で以前読んだ記憶だけを頼りに「この内容は何月何日のもの」と決めつけない（記憶違いで日付を取り違えるミスが実際に起きたことがある）。
   - 大量の日を一気に処理せず、数日〜1週間分ごとに区切り、必要なら進捗を報告する。

6. **サマリー報告**
   - 何日分を対象にしたか、何ブロックをどのノートへ振り分けたか、未分類として残したものは何かを最後にまとめる。
