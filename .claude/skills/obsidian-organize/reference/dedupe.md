# 重複・散在情報の統合 手順

同じトピックについて、デイリーノートの断片やトピックフォルダ内の複数ノートに内容が分散しているケースをまとめる。

## 手順

1. **対象トピックの特定**
   - ユーザーが対象トピックを指定していればそれに従う。指定がなければ、フォルダ名やファイル名が似ている、または`Grep`でキーワードが複数ファイルに散在しているものを候補として提示し、ユーザーに確認する。

2. **散在箇所の洗い出し**
   - 候補トピックについて、関係しそうな全ノート（トピックフォルダ内・デイリーノート内の未振り分けブロック含む）を`Grep`/`Glob`で洗い出し、実際に`Read`して内容を把握する。
   - 単なるキーワード一致ではなく、実質的に同じ主張・同じ事実を書いているか、話が違うだけで無関係かを内容ベースで判断する。

3. **統合方針の提示**
   - 統合先ノート（既存の中で最も内容が充実しているものを軸にするのが基本。適切な既存ノートがなければ新規作成を提案）を決め、各出典ごとに「何を」「どう反映するか（追記/表現の統合/矛盾があれば併記）」を箇条書きでユーザーに提示する。
   - 内容が矛盾している場合は片方を勝手に正としない。両論併記するか、ユーザーに確認する。

4. **実行**
   - 統合先ノートへ反映する。元の複数ノートは削除せず、統合先ノートへのwikilinkと「統合済み」の一言を残す（例えばノート冒頭に `→ 統合先: [[統合先ノート]]` と追記する）。完全にリダイレクトのみで内容が空になる場合でも、ファイル自体は残す。
   - ユーザーが明示的に「元ノートを削除してよい」と言った場合のみ削除する。

5. **サマリー報告**
   - 統合したノートの一覧、統合先、削除有無を報告する。
