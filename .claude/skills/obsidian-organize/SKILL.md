# Obsidian Vault 整理スキル

## 対象Vault
- パス: `C:\Users\yuuki\OneDrive\ドキュメント\think`
- OneDrive同期のみで、Gitなどのバージョン管理はされていない
- 既存のトップレベルフォルダ例: AIエージェント開発, AI活用, AI駆動開発, AtCoder, Claude, LLM, Python, RAG, Reading, Rules, github, note, キャリア, ゲーム開発, コンペティション、ハッカソン, ハッカソン, ハードウェア, ブログ, 人間関係, 仕事関連の作業, 備忘, 基礎概念, 日記メモ, 統計学, 資産系, 開発基礎
- デイリーノート: `日記メモ/YYYY-MM-DD.md`。階層化された箇条書き（アウトライナー形式）で、1日に複数の話題（例: 資産運用、開発、仕事の考え事）が混在している
- タイトル規則 (`Rules/notetitle_rules.md`): なるべく英語表記。正式名称が日本語ならそのまま日本語。「〇〇の△△」は「〇〇_△△」と書く
- タグ(`#tag`)・wikilink(`[[note]]`)・frontmatterはごく一部でしか使われておらず、統一ルールはまだ無い

作業を始める前に、上記の情報が古くなっていないか（フォルダ構成が変わっていないか）を軽く確認すること。

## 安全に作業するための原則（必読・最優先）
1. **Vaultはバージョン管理されていない。** 数ファイル〜1トピックを超える規模の変更をする前には、対象範囲と変更方針をユーザーに提示し、承認を得てから書き込む。「全部お任せ」等の明示的な指示がある場合はまとめて進めてよい。
2. **原文を消さない。** ノートを移動・統合するときは、移動元に一言（例: `[[移動先ノート]]へ移動済み`）を残すか、コメントで統合先を明示する。デイリーノートの原本自体は削除しない。「振り分け済み」であることが分かるようにするだけでよい。
3. **一括破壊的操作をしない。** 一度の作業で大量のファイルを削除・上書きしない。数件〜1トピック単位で「提案 → 承認 → 実行」のサイクルを回す。
4. **既存の書き方を尊重する。** frontmatterや絵文字を勝手に増やさない。新規ノートのタイトルは `Rules/notetitle_rules.md` に従う。既存ノートが箇条書き主体なら箇条書きのまま整理し、無理に文章化しない。
5. Vaultが `.git` 管理下になく、これから重複統合や一括振り分けのような規模の大きい作業をする場合は、作業前に一度だけ「`git init` してバックアップを取ることもできますが、どうしますか」とユーザーに確認する（毎回は聞かない。断られたら以後は聞かない）。

## モード
依頼内容に応じて以下から該当するものを選ぶ（複数可）。手順の詳細は各referenceファイルを、必要になったタイミングで読み込むこと。

| モード | こんな依頼のとき | 詳細手順 |
|---|---|---|
| 日次ノート仕分け | デイリーノート/雑多なメモを分類してほしい | `reference/daily-triage.md` |
| タグ・リンク整理 | タグを統一したい、関連ノートをリンクさせたい、MOCを作りたい | `reference/tags-links.md` |
| 重複・散在情報の統合 | 同じ話題が複数ノートに散らばっている、まとめたい | `reference/dedupe.md` |

依頼が曖昧、または「Vault整理して」のように広い場合は、まず対象範囲（例: 直近1ヶ月分のデイリーノート、特定フォルダのみ）をユーザーに確認してから着手する。

## 進め方の型
1. 対象ファイルを実際に読み込み、現状を把握する（フォルダ構成やファイル名だけで判断しない）
2. 変更方針（何を・どこに動かす/統合する/リンクするか）を箇条書きで提示する
3. ユーザーの承認を得る
4. 承認された範囲だけファイルを編集する
5. 最後に変更点のサマリー（振り分け件数、新規/更新ノート一覧など）を報告する
